# Current official OpenGhost frontend parity audit

Date: 2026-10-06. **Audit only; no implementation changes or commits made by this audit.** Native qualification is pinned to `b400581` as explained below; additional concurrent edits appeared during report writing.

## Verdict

**The native frontend is not a complete functional clone of current official OpenGhost.** It contains substantial, working native presentation and frontend services—not merely a shell—but several official paths are missing, only implemented below the UI, or disconnected from the shipped Pi adapter.

Most consequential findings:

1. **BLOCKER:** Ask/Auto/Full does not itself enforce official permission semantics. The shipped bridge only broadcasts the selection; enforcement requires an additional compatible Pi extension.
2. PDFs, office-document extraction, video attachments, pasted-file/image ingestion, attachment notes and long-paste cards are absent or reduced.
3. Mini-chat, chat-password controls and adding project folders have service code but no usable UI path. Passwords also lack a production cryptographic provider; folderless chats are not wired to their intended per-chat working directories.
4. Manual compaction, model-switch summarization, context-fullness feedback and per-chat stats are absent. Preserving an undrawn saved entry is not support for its functionality.
5. Thinking controls have no levels from the real Pi catalog and the adapter does not set thinking effort.
6. The browser panel and native browser automation exist, but the shipped Pi adapter does not connect the browser tools/state to the agent.
7. Rich rendering is extensively ported. Important exceptions include arithmetic/calculation sheets, visual diagram editing, persisted diagram edits, and native rendering bounds.
8. Several inherited native behaviors are **not official features**: reply token/time footers, automatic clipboard writes on keyboard selection, and optional plugin surfaces.

The detailed tables contain **66 non-match entries: 1 BLOCKER, 23 HIGH, 33 MEDIUM and 9 LOW**, including explicitly intentional differences—not 66 interchangeable bugs. Scoped matches are documented separately.

A passing native/fake test or a renderer screenshot does not close any of these integration gaps.

### Classifications and severity

- `MATCH`: the stated, bounded behavior has corresponding reachable implementation; not a universal pixel/OS/backend certification.
- `PARTIAL`: some of the official behavior exists, with the precise remainder described.
- `MISSING`: no implementation of the stated official capability was found.
- `WRONG`: implemented behavior conflicts with the official behavior.
- `STUB`: a visible path or acknowledgement exists without the behavior it implies.
- `NOT WIRED`: useful implementation exists, but its required UI/service/adapter connection does not.
- `INTENTIONALLY DIFFERENT`: an explicit native architectural/product choice. This still counts as a parity difference, not automatic acceptance.

Severity: `BLOCKER` = safety/trust barrier to calling the frontend equivalent; `HIGH` = substantial user workflow/functionality unavailable; `MEDIUM` = material bounded behavior/interaction difference; `LOW` = minor, conditional or platform/developer convenience difference.

Issue categories used below: **functionality, UI, behavior, integration, state/persistence, data fidelity, performance, accessibility, security, platform, scope**.

Adaptation notation: **direct** = can retain the official behavior in Qt/C++ without a new backend capability; **native** = needs a native toolkit/library implementation; **boundary** = requires external-backend/host-contract support. None means importing Electron/React into the native UI, or implementing provider/tool execution inside the renderer.

## 12. Dependency ordering for a future parity effort (not fixes performed)

1. **Safety and integration:** resolve M05/M06's actual permission provider, then B01 host tools and M01 effort; qualify against a real backend, not only fake fixtures.
2. **Context and state:** compaction/handoff/stats, mini parent context, locks and persistent payload ownership. These are prerequisite semantics for several UI paths.
3. **Attachments:** native PDF/office/video readers, asynchronous preparation, clipboard ingestion, notes, pasted-text cards and durable image previews. Review licenses before adding any dependency.
4. **Reachability:** mini/lock/folder/Add-menu controls, provider/account limits and explicit error actions, reusing the existing QML wherever possible.
5. **Rendering/input fidelity:** arithmetic sheets, visual/persisted diagram edits, composer tokens, quote/copy behavior, semantic accessibility and platform preferences.
6. **Qualification:** matched live interaction/state-transition tests, real provider failure/cancel/steer cases, screen readers/IME, browser control handoff, persisted restart behavior, and comparable long-chat frame-time/memory tests on each supported platform.

These are audit dependencies, **not authorization to implement changes**, and do not require resurrecting source-port panels or features absent from official OpenGhost.
