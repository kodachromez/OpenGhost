# Browser host-tool lifecycle (F16)

The existing OpenGhost browser UI, guest isolation, login partition and Take Control/hand-back behavior are unchanged. This supplements the ABP host-tool contract; it supersedes the pre-fix browser behavior recorded in audit §4.

## Availability and targets

- `initialize.host.tools` includes the 11 browser schemas only when the desktop browser bridge exists.
- `host.browser` is an explicit object even when closed/empty: `available`, `status` (`unavailable`, `empty`, `lazy`, `loading`, `ready`, `failed`, `gone`), `control` (`agent`/`user`), `open`, `tabs`, `signedIn`, and `signedInVerified:false`. Submission observations are **not** verified login/provider auth state.
- `host.browser.changed {browser}` notifications report lifecycle/control/context changes. Tab entries include stable `tabId`, display position `n`, `state`, `loading`, renderer `revision`, title, URL and active flag. These are hints; tool dispatch always rechecks the live target.
- All host-tool calls, including tab mutations, are serialized across chats. The target is captured at receipt, not after queuing. Optional `tabId` explicitly selects a tab; otherwise the active target is pinned. A changed/closed target fails instead of silently retargeting.
- `browser_tabs switch/close` **require `tabId`**, not the positional `tab`. `new` fails with `tab_limit` at 12 tabs rather than evicting one. User tab controls retain their existing behavior.
- Page results carry `data.tabId` and opaque `data.pageId`. `click`, `type`, `select`, `press` and `scroll` **require `pageId`** from the latest observation; other page tools may also supply it as a precondition. Navigation, another input operation, or partial/cancelled input invalidates earlier page identities. Re-snapshot after stale-target errors. Refs are usable only with their accompanying page identity, not durable element handles. Covered/moved ref targets fail before input.

## Readiness, cancellation and errors

First `dom-ready` has a 15-second deadline and rejects on close, replacement, destruction, failed initial load or crash; each caller can also cancel its readiness wait. Readiness timers and event listeners belong to one webview instance. Disposing it rejects pending readiness, removes its listeners and cancels active/queued calls pinned to that tab. Late events from an old view cannot ready or mutate its replacement. A subsequent fresh readiness attempt can recreate a failed/crashed guest. The renderer call budget is 90 seconds including its queue; the main operation budget is 75 seconds including its queue. CDP/isolated-world calls are bounded by 12 seconds, navigation by 30 seconds and loading settle by 15 seconds. User hand-back waiting remains intentionally unbounded.

Each renderer job registers its cancellation signal **before** waiting in the queue or for `dom-ready`, and rechecks it immediately before IPC dispatch. A cancellation sent before a desktop job exists therefore cannot be followed by a late dispatch. Desktop jobs register synchronously and share one cancellation/deadline barrier across CDP, JavaScript, navigation, reads, pointer feedback and delays. Cancelled queue entries never execute or release their predecessor's queue slot.

Take Control invalidates active/queued jobs immediately, but keeps the existing input shield up until desktop cancellation and navigation cleanup are acknowledged. Only then does the UI show user ownership and focus the page. Failed/timed-out acknowledgement leaves the shield in place with an error, rather than claiming control. Hand Back cannot bypass an outstanding takeover. The interrupted action stays retired even if Hand Back arrives before its result: the pending host request returns only a fresh snapshot (`status:'handed-back'`), never a replay of the old action. Further input requires a new agent request.

Cancellation/timeouts release waiters and prevent subsequent dispatches from late continuations. Stop also removes hand-back waiters without requiring the user to hand back. Navigation loads are stopped on failure/cancellation. Already-issued browser input/JS cannot be rolled back; cancellation or a timeout is not proof that no partial side effect occurred. Re-observe before retrying. Page reads/snapshots are observations, not DOM transactions.

Failures use `isError:true`, `status:'error'` (or the existing cancellation/hand-back status), text explaining the failure and `data.code`. Codes include `unavailable`, `timeout`, `wait_timeout`, `navigation_failed`, `navigation_aborted`, `tab_gone`, `guest_crashed`, `stale_tab`, `stale_page`, `stale_ref`, `stale_target`, `element_covered`, `stale_read`, `tab_limit`, `invalid_request` and fallback `browser_error`. Wait-for-text expiry and navigation failures no longer look successful.

### Navigation outcomes (issue #21)

`browser_navigate` returns the normal snapshot only after navigation completes and the page settles. DNS, network, certificate and other `loadURL` rejections fail with `navigation_failed`; hard load/settle deadlines fail with `timeout`. Readable partial content, an error-page commit or `did-stop-loading` alone is never proof of success. Failure stops the load and does not return a success-shaped diagnostic snapshot.

`ERR_ABORTED` is an explicit `navigation_aborted` failure, not a presumed successful redirect or download. Explicit user cancellation retains `cancelled`, and a timeout retains `timeout`, even when stopping the load generates an abort. Electron sometimes rejects a stopped load with `ERR_FAILED`; that remains `navigation_failed`. The requested `loadURL` promise determines its outcome, so an abort event for the *previous* superseded load is not misattributed to the new request.

Back/forward/reload require a load-completion event (or main-frame same-document history completion), and observe both ordinary and provisional main-frame failures through settling/snapshot completion. Failure is scoped to the operation and cannot be cleared by a later commit; subframe failures do not by themselves fail the main-document navigation. Missing history and page-prevented navigation fail rather than returning the old page.

## Result metadata

- Snapshots: `refs`, `coverage`, `truncated`, `scroll`, and operation-scoped `downloads`. DOM/visibility heuristics and timed quiet are unchanged; cross-origin iframes remain unreadable and snapshot/read shadow-DOM coverage differs.
- Screenshots: image plus `width`/`height` (returned image pixels), `scale`, `pageWidth`/`pageHeight` (captured CSS dimensions, **not** total document dimensions), `capture: {x, y, width, height}` (captured page rectangle in CSS pixels), `contentHeight` (total page height measured before capture), `viewportHeight`, and an explicit boolean `truncated`. Full-page capture stays at viewport width and is capped at four viewport heights, starting at `(0, 0)`. Taller pages return `truncated:true` and text stating that only the top N CSS pixels/four viewport heights were captured, the captured vertical range and total height, and that more content exists below. Pages fitting within the cap, including exactly at the cap, return `truncated:false` and text confirming complete vertical capture. Ordinary viewport screenshots also return `truncated:false`; that does not claim full-page coverage. CSS capture dimensions are independent of image resizing (maximum output width 1280); divide image coordinates by `scale` for offsets within the captured rectangle. Measurements and capture are observations, not a transaction against page changes.
- Reads: frozen HTML-derived text, not recomputed live HTML for each slice. First call omits `readId`; subsequent calls supply the returned `tabId`, `readId` and `start=data.end`. Metadata includes `start`, `end`, `total`, `hasMore`, `offsetUnit:'utf16'`, `sourceTruncated`, `truncated` and `coverage`. A refresh, navigation/input, or lost tab invalidates continuation. Source HTML remains capped at 4 Mi UTF-16 code units and each text slice at 40,000. The HTML cap is enforced by incremental serialization in the isolated guest world **before IPC**, without building the complete page's `outerHTML`; large text/comment nodes and attribute escaping are processed in bounded chunks. DOM attribute access itself still returns a whole attribute value. `sourceTruncated` means serialized content was actually omitted, not merely that the buffer reached the cap. A missing `documentElement` returns empty, untruncated HTML. Hidden text may be included; form controls, iframe content and shadow roots are omitted. These limitations are explicit, not a new extraction engine.
- Completed downloads are attributed to the guest and operation active when the download began. Later/other calls do not consume a global one-shot download list. Late completion still produces the existing UI download toast, not a claim that a different operation downloaded it.

Focused checks: `node --test test/browser-lifecycle.test.js test/browser-navigation.test.js test/browser-read.test.js test/browser-screenshot.test.js test/cancellation.test.js test/untrusted-text.test.js`, `node test/e2e/browser-lifecycle.mjs`, `node test/e2e/browser-read.cjs`, and `node test/e2e/browser-screenshot.mjs` (headless Electron, local pages only). Screenshot regressions cover short, exactly-at-cap and over-cap pages, explicit completeness/truncation text, CSS coverage versus resized image dimensions, and unchanged viewport-only behavior. Read regressions inspect the isolated evaluation/IPC return before main-process result handling, using 32 Mi-character text, attributes, comments and sibling content, native small-HTML parity, exact-cap boundaries, frozen continuation, hostile main-world getters and a missing document root. If headless Ozone is unavailable, the read check supports `OPENGHOST_E2E_OZONE=x11` with a hidden window and isolated profile.
